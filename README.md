# FOLD TEMPO · 合拍

折痕就是判定线。上界的音符自上而下落进折痕，下界的音符自下而上顶到折痕，
两条同时抵达时双手同时点，一次收两个连击 —— 把「合上手机」这个动作本身变成节拍。

## 玩法

屏幕被中间的折痕分成两半，判定线就在折痕上：

- **上界（紫）**：音符从上往下落，点**上半屏**击打。
- **下界（绿）**：音符从下往上顶，点**下半屏**击打。
- **合折**：上下两条同时到线，双手同时点，一次收两个连击。
- 在任意位置点击都算，不需要对准小按键 —— 判的是**时机**，不是位置。

判定窗口：误差 50ms 内 PERFECT，100ms 内 GOOD，超过 100ms 则断连击。
按准确率结算 S / A / B / C / D，最好成绩记在本地。

## 曲目与难度

一首 63 秒的曲子，BPM 124，A 小调，和弦进行 Am–F–C–G。
结构为 前奏 2 小节 / A 10 / B 8 / C 8 / 尾奏 4，C 段旋律升八度、加开镲，推到高潮。

| 难度 | 音符 | 密度 | 最小间隔 | 特征 |
|---|---|---|---|---|
| 轻折 EASY | 104 | 1.68/s | 484ms | 一拍一击，先建立节奏感 |
| 深折 NORMAL | 226 | 3.65/s | 242ms | 正拍 + 反拍八分，18 次双押 |
| 极折 HARD | 347 | 5.60/s | 121ms | 十六分连打，35 次双押 |

前 2 小节与最后 4 小节不出音符：前者只有 pad 与琶音，画面显示「准备」；
按开始后约 3.9 秒第一拍才到，不至于让人以为没反应。

## 关于音画同步

这套游戏最容易出错的地方不是判定，而是**谱面和音乐对不上**。
本作的做法是让两者同源：

- `tools/gen.py` 先写音乐事件（8 种乐器、1392 个发声点），
- 再从这些事件**派生**谱面，每个 tap 音符都对应一个真实发声，
- 校验脚本会反向确认：谱面里不存在「没有声音的音符」，也不存在偏离 16 分网格的位置。

所以改任何一个音符，谱面会自动跟着变，不会出现「音乐改了、谱面忘了改」的错位。

音频全部实时合成，没有任何音频文件：底鼓正弦下滑、军鼓噪声+带通、踩镲高通噪声、
贝斯锯齿+低通包络、琶音三角波、主旋律双失谐方波、铺底三角波，经压缩器与附点八分延迟输出。

播放用前瞻调度（每 25ms 检查一次，提前 140ms 排程），时钟以 `AudioContext.currentTime` 为准 ——
不能用 `performance.now()` 累加，那样一定会漂。

## 折叠屏适配

- 内屏近方形（≈2248×2480）时上下两界各得半屏，判定线正好居中。
- 横屏、窄屏各有独立布局，判定线始终在画布垂直正中。
- 全屏 `viewport-fit=cover` + 安全区留白，避开挖孔与手势条。
- 禁用双指缩放与橡皮筋滚动。

## 延迟校准

蓝牙耳机普遍有 100ms 以上的延迟，会让所有音符都判成「晚了」。
开始面板提供 ±120ms 的偏移滑块，按自己设备调一次即可，设置存在本地。

## 技术

单文件 `index.html`，无外部请求、无依赖、可离线运行。

```
index.src.html    源码模板（注入点 /*__SONG__*/）
tools/gen.py      音乐与谱面生成器（含自检）
tools/beat.json   生成结果
tools/build.py    把 JSON 注入模板，产出单文件 index.html
test.cjs          浏览器自动化验收（40 项）
```

## 验收

`node test.cjs` 会驱动真实 Chromium 跑 40 项断言，其中包括：

- 在页面内**独立复算**一遍谱面：音符是否都对应发声、是否都在 16 分网格上、上下是否均衡；
- 用**可注入的假时钟**把 63 秒曲子压成秒级测试：判定窗口边界、空击不罚、漏击判定、
  双押、全连满分、全漏评级；
- 真实 DOM 输入链：鼠标点上半屏 / 下半屏分别命中对应侧的音符；
- 真实音频：`AudioContext` 状态、调度器推进、以及**从 AnalyserNode 读实际波形能量**
  证明合成器真的在发声（不只是调度计数在动）；
- 4 种视口下判定线居中、页面不溢出、零运行时错误。
